# 鸿蒙与 Web 动作适配（客户端 0.11.0）

## 使用入口

在平板原网页小窝打开「动作 → 宠物的陪伴动作」。与 Web、Windows 桌宠共用 `static/js/den/action-catalog.js` 的 25 个动作定义：安静陪伴、散步、左右探身、嗅闻、坐下、睡觉、摸头、开心、伸懒腰、抖毛、舔鼻、摇尾、抬爪、邀玩、吃惊、撒娇、打哈欠、警觉、害羞、竖耳、倾听、挥爪、说话、咀嚼。

小窝面板另有跑动、小跑、走近主人、自由活动、起身五个指令，主动作栏提供停止按钮。说话和咀嚼在这里仅播放动作，不发送聊天、不播放声音、不扣除食物；文字/语音对话、喂食饮水仍使用原入口及业务规则。

照料、玩具、捡球、拖放、手势/面对面互动、成长和自主行为仍由同一套 Web 小窝逻辑执行，保留原有页面及操作。坐卧先完成起身，再执行移动；连续选择取消旧指令。骨骼动作采用 260 毫秒归一化权重过渡，步频按时间平滑，面部表情层独立保留。自定义模型缺少动作时按钮禁用，不用别的动画冒充。

## 原生独立入口与绘制边界

连接设置中的「原生宠物互动」支持共享的 25 个动作，加跑动、小跑、起身，共 28 个动作选项；另有走过来及暂停/恢复。ArkTS 状态机处理进入坐卧、起身、排队的新指令、加减速、转向及后台暂停。生成文件 `NativeActions.ets` 由 `node scripts/sync_harmony_actions.cjs` 同步，`--check` 检查一致性。

原生独立入口不重复实现账号、照料消耗、种植或摄像头业务，这些完整功能位于原网页小窝。原小窝的混合原生绘制白名单仍为空，沿用已修复的 Web 绘制，避免此前原生报告就绪但模型消失的问题。本次不是全部业务的 ArkTS 重写。当前 SDK 的原生 Animation 接口不提供混合权重；原生使用完整进入/退出动画串联，不能将 Web 的 260 毫秒混合测试视为原生 GPU 混合验证。

## 验证记录（2026-10-18）

- 四个默认模型的 25 个动作均有独立动画数据，原生目录 28 项均可解析；动作混合、连续打断、坐卧转移动、暂停后回调和停止回归通过。
- Chromium 触屏环境逐一播放柴犬、哈士奇、猫咪、德牧的 25 个动作，并检查睡觉后散步/跑动/小跑与停止。
- MatePad Air 的 ArkWeb 真机逐一触控播放猫咪 25 个动作，检查三种移动和停止，页面无脚本异常。其他三宠的全套触控记录来自 Chromium，并非四宠全部完成真机验收。
- 客户端 0.11.0 已使用本机签名编译并安装；签名资料不入库。原生逻辑测试使用 SDK 替身，不代表独立原生入口全部动作的真机视觉验收或 FPS 承诺。
- 对话动作、表情、喂食、玩具/拾取、移动、鸿蒙桥接相关回归通过；没有为测试扣除生产食物、发起付费对话或开启摄像头。

真实浏览器用 `node test/companion_actions_browser.cjs`，需先启动独立的 `test/desktop_transfer_server.py`（5091）。可用 `PET_ACTION_PETS=1,2,3,4` 选择宠物；`PET_DEVICE_CDP` 指向已授权调试的 ArkWeb 时使用当前真实登录页面。后者会操作当前宠物，测试前应确认设备正用于验收。
