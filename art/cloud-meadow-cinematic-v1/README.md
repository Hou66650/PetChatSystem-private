以 `art/cloud-meadow-v2` 中带大草坪的岛屿布局为基准，结合早期温室概念的建筑细节，制作可编辑的 Blender 场景。这里的四张图均来自实际网格的 Cycles 渲染，不是 AI 生成的成品效果图。它是一版细化母版，尚未完成桌面客户端迁移，也不表示与早期概念图逐像素一致。

## 本次细化

保留已有可活动大草坪的布局与道路中心线。重做 130,520 片树冠叶子的弯曲轮廓和叶脉 UV；新增 75,064 根弯曲细草，以及成簇三叶草、蕨类羽状叶和小花。温室增加实体窗框、装饰柱和四毫米玻璃片；桥增加分块石材和拱券。溪流增加几何涟漪、河床卵石和透明瀑布片，陶盆带内壁、卷口和土壤颗粒。

农场里的成熟植物与猫窝用于场景展示，使用项目原生资产。没有读取、改写任何账号的种植存档，也没有把展示植物写进生产槽位。

## 重建与校验

在仓库根目录执行（PowerShell）：

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b --python scripts/blender/build_cinematic_meadow.py
python scripts/validate_cinematic_meadow.py
```

快速试渲染：在构建命令末尾加 `-- --preview --no-export`。试渲染为 1280 × 900，正式输出为 2400 × 1688、96 samples、AgX 色彩管理。脚本使用固定种子，要求可用的 OptiX 设备，避免无提示地切到 CPU。本次设备为 NVIDIA GeForce RTX 5060 Laptop GPU。

完整母版与导出模块体积较大，不重复放入 Git；仓库保存构建代码、正式渲染图和报告。它们可以通过仓库内原生模型、贴图和脚本重新生成，不依赖个人照片、API Key 或在线生成服务。Blender 不同版本/驱动的渲染输出及 GLB 序列化字节可能不同，重新构建后应使用新生成的报告校验。

## 客户端接入约定

1. 单位为米；Blender 为 Z 向上，GLB 自动转换为 Y 向上。所有模块共用原点，不能分别自动居中或归一化缩放。
2. `base-island`、五个 `canopy-*`、`architecture`、`botany`、`water` 组合构成静态景观；`demonstration-props` 可选，实际游戏应替换为存档驱动的宠物设施和植物。
3. 云海体积、天空和摄影灯光保留在 Blender 中，未导出到 GLB。客户端需重建对应天空/云雾与曝光；不能期待直接加载 GLB 就得到同样的 Cycles 画面。
4. GLB 内嵌现有 PBR 贴图和新材质贴图。母版额外使用的世界坐标微凹凸是 Blender 节点，目标引擎需要重建或烘焙；折射、水体、双面植被也需逐项检查。
5. 视觉细节网格不是碰撞体。导航仍参考 `static/js/den/mistwood-layout.js` 与 `static/data/farm-layout.json`，客户端另做简化碰撞和导航烘焙，再验证桥、入口、水岸、摆放和传送门通路。
6. 本版强调细节，用于资产审查。尚无桌面客户端 FPS 验收；后续需要植被实例化、分区加载、纹理压缩和 LOD。当前网页资源入口没有替换为这些高精度文件。

## 校验范围

校验器核对源文件哈希、10 个 GLB 的长度/哈希、内嵌纹理、所有位置坐标的有限值与范围、模块间重复网格名称、四张正式图的尺寸。人工查看全景、温室、草坪与俯视图，检查过曝、穿插和构图。校验通过不替代目标引擎中的材质、碰撞和性能验收。
