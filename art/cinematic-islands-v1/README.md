# 三座岛屿的离线高精度版本

本目录是樱花庭院、雪境木屋、山岭营地的 Blender 高精度制作版本，供细节审阅与后续电脑客户端使用。没有替换 `static/` 中的在线模型，没有修改网页场景入口或读取账户存档。图片来自实际模型的 Cycles 渲染，不是概念效果图。

## 交付文件

| 岛屿 | 目录 | 主要细化内容 |
| --- | --- | --- |
| 樱花庭院 | `sakura/` | 弯曲五瓣樱花、花蕊、地面落花、针叶树与草蕨；茶亭瓦脊、斗拱、格栅、茶具和坐垫 |
| 雪境木屋 | `snow/` | 针叶与枝上积雪、起伏屋顶雪层、檐口冰柱、结冰池面裂纹；木屋百叶窗、铰链、柴堆和暖窗光 |
| 山岭营地 | `camp/` | 针叶树与草蕨；石塔压顶、栏杆、屋顶瓦片与铜饰，木屋木作、窗扇、柴堆和桥面 |

三座岛均补充溪底卵石、起伏水面、分股瀑布、木石材质与建筑边缘倒角。保留原有岛形、建筑位置和活动通道；没有新增可运行的碰撞或寻路逻辑。

每个目录包含：

- `01-panorama.png`：全景，2400 × 2000。
- `02-architecture.png`：建筑近景，2400 × 2000。
- `03-plan.png`：俯视布局，2400 × 2000。俯视图关闭云层并使用中性底板，便于查看地形。
- `island-master.blend`：可编辑母版，贴图打包在文件内，仅保存在本机。
- `client-staging/`：同一原点的四个 GLB 模块，仅保存在本机：`landscape`、`architecture`、`vegetation`、`water-snow`。
- `build-report.json`：输入/母版/导出文件哈希、几何统计、细节数量、GPU 信息。

母版按集合区分原始地形、建筑工艺、精细植物、水雪细节。`90 Presentation only` 内的灯光和展示背景不属于运行时地图。尺寸采用米，Blender 为 Z 向上，GLB 导出为 Y 向上；导入客户端时四个模块必须保持共同原点，不能分别居中。

## 构建与验证

使用 Blender 5.2、Cycles、RTX 5060 Laptop GPU / OptiX。固定随机种子，预览为 24 采样，正式渲染为 96 采样并降噪。构建脚本要求可用的 OptiX GPU，失败时不宣称完成 GPU 渲染。

在 `D:\PetChatSystem` 执行：

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b --python scripts/blender/build_cinematic_islands.py -- all
& 'C:\Users\17958\.conda\envs\qijin666\python.exe' -X utf8 scripts/validate_cinematic_islands.py
```

将 `all` 替换为 `sakura`、`snow` 或 `camp` 可单独重建；附加 `--preview` 只生成预览和母版，不导出模块。预览会更新对应母版与报告，交付前应再次执行正式构建及验证。

`source/` 保存首次构建时冻结的三个源 GLB 与布局 JSON。三个源 GLB 是本机既有美术资产，目前不在 Git 中；**仅克隆代码仓库不足以复现**。迁移工作站时，请复制整个本目录（含 `source/`、母版及 GLB），并携带 `scripts/blender/` 中的构建脚本及依赖。源文件哈希记录在报告中，后续重建优先使用冻结副本。

Git 保存脚本、文档、布局快照、渲染图及检查报告；大体积母版、GLB 和预览图不提交。请另外备份本地完整制作目录。

`validation.json` 检查文件哈希、GLB 长度、内嵌贴图、全部顶点坐标和索引、渲染尺寸。`web-unchanged.json` 记录正式构建前后在线源模型、布局脚本及小窝模板的哈希一致性。视觉审阅与文件完整性检查分开进行。

## 客户端接入边界

这些是高精度视觉资产，尚未完成游戏运行时验收。后续需要独立制作碰撞体、导航网格、LOD、实例化/分区加载与遮挡剔除，并在目标客户端测量帧率和显存。不能把离线渲染耗时或面数当作实时性能结论。

GLB 包含几何与可导出的 PBR 贴图；Blender 程序化微表面、次表面散射、灯光和体积云不保证跨引擎一致。客户端需重建或烘焙相关材质，尤其验证雪、薄叶、玻璃、水和透明排序。瀑布目前是静态几何展示，流动动画需在引擎内接入。

本版没有把网页替换为高精度资源，也没有执行客户端迁移。
