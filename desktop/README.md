# 现实传送门与 Windows 桌宠

服务端、网页和桌面客户端需要一起更新。桌面传送使用协议 2；旧服务端会提示升级，新服务端上未完成准备确认的旧桌面客户端会超时返程。

## 使用

1. 在 `desktop` 目录运行一次 `npm ci`，随后用项目根目录的 `Start-Desktop.cmd` 启动。
2. 在小窝选择“动作 → 双传送门 → 现实传送门”。宠物到门口后点击“确认出发”。
3. 将网页根地址和一次性配对码填入客户端。地址必须连接同一个服务端；本机可用 `http://127.0.0.1:端口`，远程连接使用 HTTPS。
4. 保持小窝页面可见，等待模型与已穿饰品准备完成。宠物走入岛上的门，再从桌面光门走出、站稳，随后自由活动。
5. 点击宠物可摸摸，右键的“陪伴动作”或控制台动作选择器可让它做动作；“自主活动”默认开启，可关闭后安静陪伴。右键仍可召回。软件感知默认关闭，只在自由活动阶段允许开启。
6. 到达桌面后，在控制台“聊聊今天”输入消息，或右键宠物选择“和它聊天”。沿用原有宠物人格、记忆；回复旁点击“用它的声音朗读”使用已选专属音色或原默认音色。“停止朗读”立即停止当前音频。

7. 在“提醒与专注”选择类型、填写内容和时长，点击“生成审批卡”；也可在聊天框输入“5分钟后提醒我喝水”或“专注25分钟”。核对卡片后点击“批准并执行”才会创建提醒或开始专注；“拒绝”关闭审批，已开始的任务可“取消计时”。这些固定句式直接生成审批，不调用模型。

提醒按生成审批卡时计算到点时间，专注从批准时开始；卡片显示按服务器时间校准的剩余倒计时，归零后等待后台确认完成。审批最多保留 5 分钟，且不能晚于提醒到点／专注最晚开始时间；每个账号同时只能有一个专注计时。时长至少 10 秒，必须在本次行程最迟返程前结束，超出时会要求缩短，不会偷偷调整。召回、断线超过 45 秒或关闭工具会取消未完成效果，已完成事实保留。

到点后客户端尝试发送系统通知。任务卡分别显示“设置成功”“计时效果”和每次通知的状态；“系统报告已显示”不代表你已读。没有可确认回执时显示“通知结果未知，可能已经显示”，不会自动再次发送。点击“再次投递…”后，需要确认可能重复才会产生新尝试，最多 5 次，旧记录保留。系统禁止通知时仍应以任务卡状态为准。

当前开放单宠聊天、朗读、提醒与专注，没有麦克风通话。服务端 `TOOLS_ENABLED=false` 可单独关闭任务工具，`DESKTOP_AGENT_ENABLED=false` 同时关闭桌面聊天／朗读／工具，配对与召回保留；两个开关默认 true。消息与语音使用现有供应商配置，未配置语音服务时不显示朗读按钮。客户端和服务器需同时更新，新客户端要求服务器提供资源 manifest 和任务 API。

关闭长期记忆时，回复正文只在服务器内存保留最多十分钟；重启或缓存失效后，同一请求不会重新调用模型。客户端不会自动重发聊天或语音；未知结果会明确报错。召回或档案／声音版本变化会清空控制台本次显示并停止朗读；开启记忆时原聊天历史仍按既有规则保存。

启动器默认地址仍为本机 5002，请按实际服务地址修改。网页的登录账号决定传送哪只宠物；客户端只持有本次行程凭证，不保存账号密码或长期凭证。

## 阶段与故障恢复

数据库继续用 `pairing / active / returned` 管理行程互斥，在 active 行程上增加 `phase` 和 `phase_started`：

| 阶段 | 完成条件 |
| --- | --- |
| preparing | 主进程下载模型及已装备饰品，渲染器解析并确认挂点完整 |
| entering | 桌面 `ready` 确认后，网页完成入门裁切动画并提交 `depart-complete` |
| emerging | 桌面完成出门、站稳，提交 `arrived` |
| roaming | 开启桌面移动、互动和轨迹记录 |

确认接口可重试，阶段不能倒退或越级。准备超时为 90 秒，入门和出门各 20 秒，心跳中断 45 秒后返程；截止时间在请求触发的清理中检查。准备失败、关闭客户端或取消会结束行程，异步资源返回不能激活旧行程。准备和穿门期间不产生探索奖励。

桌面行程从网页确认出发、创建行程起最多 30 分钟，配对与准备时间也计算在内。配对、状态和心跳响应提供 `expiresAt` 与 `serverTime`（Unix 秒）；心跳不会延长截止时间。控制台按本机时区显示最迟返程时间，召回、断线和资源准备失败可能更早结束行程。

门户错误响应保留 `error` 文案并增加 `code`：`TRIP_ENDED` 表示行程已失效，`TRIP_NOT_READY` 表示穿门尚未完成，其他既有错误为 `PORTAL_ERROR`。桌面仅在 HTTP 409 且 code 为 `TRIP_ENDED` 时立即收起宠物；普通业务冲突和无 code 的旧 409 只报告错误，后续由心跳或断联超时协调。任务 API 使用 `FOCUS_CONFLICT`、`APPROVAL_CLOSED`、`TRIP_DEADLINE` 等独立错误码，业务冲突不会召回宠物。

网页用门平面裁切宠物及饰品，退出阶段恢复原材质；外出时禁用旧的“隐藏宠物自动恢复”兜底。鸿蒙混合渲染在穿门阶段使用 Web 画面，避免原生宠物绕过裁切。

桌面移动使用 DIP 坐标、加减速和有限转向速度，按镜头投影与模型缩放换算步频。当前支持主显示器工作区，不包含跨屏迁移、桌面窗口碰撞或逐足 IK。出门光门是运行时几何效果。

## 桌宠动作

猫咪、柴犬、哈士奇、德牧的当前默认模型各支持 25 个动作，使用模型原有的独立骨骼动画，不以改名字重复计数：

| 类别 | 可用动作 |
| --- | --- |
| 日常陪伴 | 安静陪伴、散步、向左探身、向右探身、嗅一嗅、坐下陪你、趴下打盹 |
| 互动表达 | 享受摸头、开心一下、摇尾迎接、抬爪问好、邀请玩耍、撒个娇、挥爪招呼、张嘴回应 |
| 自然小动作 | 伸懒腰、抖抖毛、舔舔鼻子、吃惊张望、打哈欠、警觉巡视、害羞回望、竖起耳朵、歪头倾听、嚼嚼嘴 |

自主活动会选择已适配动作，避开最近六个小动作；短动作播放一次后恢复陪伴，坐下／打盹按限时休息。散步是真正的桌面移动。张嘴回应和嚼嘴仅是姿态动画，不代表已播放语音或消耗食物。自定义模型只展示实际具有动画的选项；坐卧还要求具备进入和起身动画。

桌面专用动画控制器以 260 毫秒平滑权重切换动作，处理连续打断，完成后释放旧动作；坐卧切换先起身，主进程收到本次动作序号和模型的站立就绪回执后才移动窗口。行走步频和朝向按时间平滑，绘制预算为每秒 60 帧（实际帧率受设备负载影响），静止时不重复调用窗口定位。新增动作在行程快照中映射为兼容的基础姿态，不扩展奖励事件或改变小岛上的动画控制器。

## 验证

- `python -m unittest discover -s test -p test_portals.py`：阶段、授权、幂等、超时、行程互斥和私有模型。
- `node test/desktop_motion.cjs`：转向、加速度、限速、到达和负原点工作区。
- `node test/desktop_actions.cjs`：四只实际 GLB 的 25 个独立动作、资产缺失、连续打断、一次性播放、坐卧起身、移动门控、混合权重归一与旧动作清理。
- `node test/desktop_contract.cjs`：OpenPets 原源码行为对照、独立请求取消、缺失动作回退；测试需要支持 `stripTypeScriptTypes` 的 Node 运行时，桌面运行本身不依赖此 API。
- `python -m unittest discover -s test -p test_desktop_agent.py`：原身份／音色、并发去重、未知结果、关闭记忆、召回和版本变化；使用隔离数据库及模型／音频替身。
- `python -m unittest discover -s test -p test_desktop_tasks.py`：审批、幂等、跨宠专注互斥、独立调度器、召回与迟到通知竞争、人工重试、40 个活跃效果及模型虚假成功隔离。
- `node test/desktop_notifications.cjs`：通知调用前取消、调用异常、未知回执、迟到系统回执和每次尝试至多调用一次。
- `node test/portal_approach.cjs`、`node test/portal_confirm.cjs`：真实网页回调的到门与确认逻辑。
- 先启动 `python test/desktop_transfer_server.py`，再运行 `node test/desktop_transfer.cjs`：隔离数据库，实际 Chromium + Electron 主进程、GLB 和饰品，慢加载、出入门、聊天与原音色、提醒审批／到点／系统通知回执、拒绝审批、取消专注、召回、饰品失败及加载中取消。会实际发送一条测试通知。需要 Playwright；可用 `PET_TEST_ELECTRON` 和 `PET_TEST_CHROME` 指定程序路径。
- `desktop/node_modules/electron/dist/electron.exe test/desktop-render.cjs`：透明窗口渲染和门户 DOM 回归；可用 `PET_DESKTOP_TEST_GLB` 提供本地定制模型。

`desktop_transfer.cjs` 同时运行 `desktop_actions_browser.cjs`：通过控制台逐个播放 25 个动作、检查真实 GLB 动画与混合权重、保存关键姿态截图、验证起身期间窗口不移动，并采样实际绘制帧率。Windows 下启动测试服务建议设置 `PYTHONUTF8=1`。测试账号、截图和数据库均为临时产物，不读取用户运行数据库、不消费模型账户额度。

后续智能体开发的实施边界、阶段和未完成项见 [桌面智能体实施记录](../docs/desktop-agent-implementation.md)。
