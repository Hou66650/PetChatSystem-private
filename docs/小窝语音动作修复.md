# v1.4.2 小窝语音动作修复

## 原因和复现

原链路为：语音回复完成 → 排队调用文字模型分析动作和记忆 → 归档完成 → 判断是否仍是最新回合及是否超出 30 秒 → 执行动作。

隔离环境真实接口复现：`坐下` 在约 3.5 秒后返回 `sit`；`休息` 在约 9.3 秒后返回空动作。这说明短动作指令完全依赖模型会漏判；排队、慢请求或下一轮对话还会让动作在开始前过期。

## 修改

- `DialogueActions.parseCommands` 使用整句语法识别明确短指令；`休息` 映射为趴下休息，支持最多三个组合动作、宠物称呼、礼貌前缀和转写标点。无法完整匹配的内容交回原有模型流程。
- 最终用户转写到达时，共享 `RealtimeUI` 即向小窝派发短指令。语音回复、记忆归档继续原流程；已执行的短指令不重复应用归档返回的动作。
- 通过 committed item 对应回合绑定迟到 ASR，避免上一句话控制新一轮。保留手动中断、切宠、挂断及插话的取消语义。
- 文字输入使用相同解析器；执行中的对话动作可以在文字回复等待期间完成走动。

## 验证

- `node test/dialogue_command_regression.cjs`：9 项通过，覆盖语法、否定/提问/引用不走快捷路径、ASR 插入标点、提前动作、重复去除、迟到转写、人工取消、切宠以及复杂请求回退。
- 原 `realtime_regression.cjs` 12 项及 `realtime_error_regression.cjs` 10 项全部通过。
- 使用合成 PCM 连接真实 GLM WebSocket，实际共享 Client → Controller → UI 收到“请你坐下。”“请你休息一下。”，分别派发 `sit`、`lie_down`；两个动作派发时归档完成数均为 0，两个归档返回后的动作均标记为不可重复执行，零服务错误。
- 隔离网页中确认“坐下”“休息”经过真实 Blender 动画完成，页面状态为“动作已完成”。
- 正式本机页面 `http://localhost:5002/den` 返回 200，显示 v1.4.2，包含提前语音动作回调。

测试使用合成语音和隔离数据库，没有测试用户此刻的物理麦克风。上述“否定不触发”专指新增快捷解析器；复杂自然语言仍由原有模型计划与原文依据校验处理。
