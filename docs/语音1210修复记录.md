# v1.4.1 连续语音错误修复记录

2026-10-13，针对“小窝语音聊完一两句后提示服务错误”的反馈。

## 复现与原因

- Flask 的会话签发与语音归档接口均返回 200。错误来自浏览器直连 GLM 的 WebSocket，普通 Flask 访问日志不包含该错误。
- 原客户端每轮归档后发送只有 `instructions` 的 `session.update`。真实连续三轮实验在第二轮复现：`code=1210`、`type=session_update_validate_error`、`message=API 调用参数有误，请检查文档。`。
- 服务端随后仍发送 `session.updated`，下一轮也能继续回答。因此，单凭收到这个错误就调用 `controller.stop()`，把可恢复的配置更新异常升级为整场通话中断，是用户反复看到通用错误提示的直接原因。
- 单独对照实验：完整配置更新得到确认；后续仅含 instructions 的更新出现同一 1210 错误。错误后的确认可能包含旧 instructions，不能只数确认事件就判定更新成功。
- [GLM 官方协议](https://github.com/MetaGLM/glm-realtime-sdk/blob/main/GLM-Realtime-doc-for-llm.md)列出 session.update 的音频、VAD、beta_fields 参数，并说明多数 error 事件可恢复，会话仍保持打开。

## 修复

- 更新使用完整配置，保留音频格式、VAD、音色及通话模式。
- 合并待更新指令，跳过已生效的相同内容；等用户说完及正在生成的回复结束后串行发送，避免多份配置同时在途。
- 核验服务端回显指令；收到拒绝、旧配置回显或 10 秒没有确认时，不再循环更新当前通话。已保存记忆会在下次通话签发时重新载入。
- 可恢复错误只显示面板提示，保持通话；初始化或认证等致命错误仍停止，并保留错误码。小窝和聊天页共用修复。
