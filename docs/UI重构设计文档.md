## 二、设计规范（新设计系统）

### 1. 设计关键词
**温暖 · 治愈 · 柔软**。基于现有宠物图片暖色调（米白、蜜橙、暖棕）统一全套页面。

### 2. 色彩（正式 token，CSS 变量 `--` 前缀）

| token | 色值 | 用途 |
|---|---|---|
| `--c-primary` | `#FF9E58` 蜜橙 | 主按钮、选中态、强调 |
| `--c-primary-deep` | `#E8833C` | hover / active |
| `--c-bg` | `#FFF8F0` 奶油白 | 页面底色 |
| `--c-card` | `rgba(255,255,255,.88)` | 卡片底（透出背景图） |
| `--c-text` | `#4A3B32` 暖棕黑 | 主文字（奶油底上 10.16:1；蜜橙底上 5.24:1，兼作按钮文字色；气泡橙底上 8.7:1） |
| `--c-text-sub` | `#7A695D` | 次文字/时间戳（奶油底上 **4.98:1**，≥4.5 达标；v2 的 #9C8A7E 仅 3.14:1 已弃用） |
| `--c-bubble-user` | `#FFE3C9` 奶油橙 | 用户消息气泡（正式入板） |
| `--c-bubble-pet` | `#FFFFFF` | 宠物消息气泡 |
| `--c-link` | `#A85416` 深蜜橙棕 | 链接默认色（奶油底 5.05:1 / 白底 5.32:1；白气泡内 Markdown 链接达标） |
| `--c-success` | `#5BB98C` / `--c-danger` `#E5735B` / `--c-danger-bg` `#FDEEEA` | 提示 |
| 紫色系 | 全部下线 | |

### 3. 字号与间距阶梯

- 字号：页头 24px / 卡片标题 18px / 正文 15px / 辅助·时间戳 12px（时间戳并入 12px 档，不设 11px）
- 字体：`"PingFang SC","Microsoft YaHei",system-ui,sans-serif`；标题装饰字用系统圆体链 `"Yuanti SC","YouYuan","幼圆","Microsoft YaHei"`，**不引入新字体文件**
- 间距阶梯：4 / 8 / 12 / 16 / 24 / 32（px），所有内外边距取阶梯值

### 4. 形状与阴影
卡片圆角 16px；按钮胶囊 999px；输入框 10px；阴影 `0 4px 16px rgba(74,59,50,.10)`，hover `.18`。

### 6. toast 行为规格
顶部居中下发，`top:16px`；成功 2.5s / 错误 4s 自动消失；最多叠 3 条（超出挤掉最旧）；点击立即关闭；入场下滑+淡入动画。API：`toast(msg, 'success'|'error'|'info')`。

## 三、逐页改版方案

### 1. 聊天页 `/gpt`（重点重构）

**布局线框（含尺寸）：**

```
┌──────────────────────────────────────────────────┐
│ 顶栏 56px：logo · 当前宠物名 ─────────── [日记][反馈][PDF][⚙] │
├──────────────────────────────────────────────────┤
│ 宠物选择条 72px：(48px 圆头像×4) + (＋上传)          │
│   选中态：2.5px 蜜橙描边 + 底部名字 12px；自定义头像为第5个 tile │
├──────────────────────────────────────────────────┤
│ 消息区（flex:1 滚动）                                │
│  · 气泡 max-width 72%（<768px 时 85%）              │
│  · 消息间距 12px；时间戳 12px --c-text-sub 在气泡下方   │
│  · 宠物气泡带头像 36px；AI 回复经 marked 渲染 Markdown  │
├──────────────────────────────────────────────────┤
│ 输入区 64px：自动增高输入框(1-3行) + 发送按钮 88×40      │
│   Shift+Enter 换行；Enter 发送；第 3 行后内部滚动不撑高   │
└──────────────────────────────────────────────────┘
```

**验收基准（可测）**：1280×720 视口下，顶栏+选择条+输入区+≥3 条消息同时可见、无需滚动页面本身。

**响应式**：≥1024 桌面如上；768–1023 宠物选择条头像 40px、顶栏图标按钮只留图标；<768 顶栏折叠汉堡、选择条横向滚动、输入区 `padding-bottom: env(safe-area-inset-bottom)` 防软键盘遮挡、发送按钮 64px 宽。

**交互修复明细：**
- **发送流程（B2）**：点击/Enter → 按钮进 loading+disabled、输入清空（发送后不保留草稿；切换宠物时草稿保留）；消息区尾部显示"◯◯◯ 跳动"的"柯基正在输入…"指示；成功后指示消失、气泡淡入；**失败**（网络/503）→ 追加错误气泡（--c-danger-bg 底）内附「重试」按钮，点击重发上一条，按钮恢复可用
- **空状态（首访）**：无历史时自动插入当前宠物的打招呼消息（本地预置文案，如柯基"汪！我是球球，今天想和我聊点什么呀？"，不入 localStorage、不入 LLM 上下文）
- **宠物切换语义（B3 定稿）**：聊天记录为**全局单流**（不按宠物隔离），每条记录带 `petId` 标记；切换宠物时：当前输入框草稿保留；消息区插入一条居中分隔"—— 现在和 猫咪 聊天 ——（仅前端渲染）；LLM 上下文仍为最近 20 条全局历史（现有后端行为）；背景图切到该宠物背景
- **宠物切换的后端机制（核对依据）**：现有协议为 `POST /get_gpt_response` 消息体携带 `petId` 字段，后端 `chat_service.handle_chat()` 按 petId 从宠物注册表加载人设（重构后端已实现并实测：e2e 第 4 节 petId=1/3 切换对话人格均正确）。页内 tile 点击仅改变前端 `currentPetIndex`，下一条消息的 petId 随之变化，**后端零改动**；`?pet=N` 只是页面加载时的初始预选，与页内切换同一条链路
- **改名/清空/模型（B5/B7/B11）→ 设置弹层（⚙）**：居中模态 360px：`你的昵称` input ｜ `宠物昵称` input ｜ `对话模型` select（**glm-4.5-flash → "标准（推荐）"** 映射，取自后端 models 数组，无映射时显示原名）｜ 分隔线 ｜ `恢复默认头像` btn-outline（=原"恢复/改变"，点击清除自定义头像并从选择条移除）｜ `清空聊天记录` danger btn（二次确认文案："确定要清空所有聊天记录吗？清空后无法恢复"）｜ `保存并关闭` primary
- **头像上传（B6 定稿）**：选择条末尾"＋"tile → 文件选择器（accept image/png,jpeg,webp，≤8MB，前端预检+后端校验）→ tile 变 spinner"生成中…"（约 1 分钟，期间可继续聊天）→ 成功：新增自定义头像 tile 并自动选中（聊天头像用它，人设仍是当前所选宠物），URL 存 localStorage `customAvatar`（跨会话保留）→ 失败：toast 显示后端原因。**路径映射**：文件落盘于项目 `uploads/avatars/`（后端 Config.AVATAR_DIR），由 Flask 路由 `/media/avatars/<文件名>`（routes/main.py::serve_avatars）对外提供，localStorage 存的是该 URL
- **历史恢复（B8）**：进入页面从 localStorage 恢复**最近 50 条**渲染（按 petId 显示对应头像）；localStorage 不可用（隐私模式）→ try/catch 降级为不持久化，顶部 toast 一次性提示"当前浏览器不保存聊天记录"
- **其他**：时间戳移气泡下方（B9）；移除樱花特效、`<pre>`、jQuery、Google Fonts（B10）；进入页面自动 focus 输入框；Esc 关闭弹层；图标按钮均有 aria-label

**localStorage 规格**：
- `chatHistory`（沿用现有 key）：`[{sender, message, role:'user'|'assistant', petId, ts}]`；旧格式条目（无 role/petId）保留供日记显示、不入 LLM 上下文（后端已有此行为）；超过 50 条时截最旧
- `customAvatar`：`'/media/avatars/xxx.jpg'`；`userPrefs`：`{nickname, petNickname, model}`
- 与日记页数据源：同一 `chatHistory`（单数据源，无一致性风险）
