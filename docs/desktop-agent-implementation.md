# 桌面到达后的智能体开发

## 基线与实施状态

以用户提供的桌面后续开发方案为基线：沿用 Flask 智能体、账号与宠物身份、人格、记忆、声音和 GLB。已核验并选择性移植 OpenPets 指定提交的安全状态校验与反应枚举，保留 MIT notice；没有接入第二套智能体、IPC、记忆或 TTS。来源和适配边界见 `desktop/vendor/openpets/README.md`。

### 第一阶段：兼容入口与行程协议

- `chat_service.handle_chat` 保留 Web／鸿蒙接口及同源检查，身份由签名 session 解析；缺省 petId 仍为 1，只有 den 入口能产生原有小窝动作，mobile／desktop 等客户端自报 surface 不获得桌面权限。
- 新增内部 `chat_for_owner(owner, pet_id, data, surface=...)`。调用方必须先完成身份授权；正文 ownerId、userId、petId 和 surface 无法覆盖显式参数。只需 Flask app context，不依赖请求、Cookie 或浏览器默认身份。未知账号、无效宠物直接失败；第一阶段仅开放 chat／den，第二阶段新增受行程保护的 desktop 调用。
- 档案 scope 根据显式 owner 计算，保持现有账号 scope 值不变。语音回执仍核对账号 scope 和档案 revision；历史、共享事实与宠物专属记忆保持既有存储规则。
- 门户错误加入机器码；业务 409 不再被桌面误认为召回。真正失效的 token／行程返回 `TRIP_ENDED`，未完成穿门返回 `TRIP_NOT_READY`。
- 行程公布绝对 `expiresAt` 与 `serverTime`（Unix 秒）。30 分钟从行程创建起算，心跳不续期；控制台显示截止时间。到期检查仍由请求触发，不是后台调度器。

第一阶段没有变更数据库结构，也没有部署到用户运行环境。

### 第二阶段：单宠桌面聊天与原音色

- Electron 使用 `TripContext` 拥有窗口、动作、位置、心跳、感知进程、事件队列、请求取消器、计时器和 generation。每次传送创建新宠物窗口；IPC 从可信主 frame 的 webContents 映射行程，客户端 tripId 只可作为迟到消息校验。仍限制一个活跃桌宠，未开放多宠。
- 模型与每件饰品通过服务端 manifest 提供 SHA-256，主进程限制下载大小并校验 GLB 头和哈希；渲染器与运动事件同时匹配 trip、generation、模型 hash。资产变化会要求重新传送。指定动作缺失时回退 idle，连 idle 也没有则静止，并显示未适配提示。
- `manifest/chat/speech` 位于现有 Bearer 门户接口，聊天和语音仅允许 roaming 阶段。owner、pet 来自行程，正文不允许传身份、模型或供应商音色。纯聊天不派发场景动作；模型自称完成也不会产生 success 反应。
- 聊天沿用原人格和记忆；朗读解析账号当前为该宠物选定的专属音色，否则使用原默认音色。控制台每条回复可点击朗读，超过 1000 字明确只读前 1000 字；一次只播放一段，可随时停止。未接麦克风或实时语音通话。
- 增量表 `desktop_agent_requests` 只记录身份、行程、操作、请求编号、内容哈希、上下文版本、执行状态和时间，不保存正文或音频。相同请求并发仅一个执行，同编号不同内容返回 REQUEST_CONFLICT；执行结果未知不自动重新调用。
- 回复／音频缓存在进程内最多十分钟，最多 128 条且合计 32 MiB。开启记忆时，重启后可以从现有聊天历史找回已确认回复；关闭记忆后缓存失效或进程重启返回 RESULT_UNKNOWN，绝不重新生成。音频缓存失效也不自动重新合成。此机制只覆盖聊天／朗读，尚不是工具副作用事务。
- 版本绑定账号、宠物、行程、档案 revision、人格、选定声音、模型与饰品 hash。写入聊天历史前在数据库事务内再次检查行程与版本，返回回复／音频前再检查；召回、断线、版本变化时中止本地请求、停止播放、清空控制台本次显示。服务器不能强制中止已发往模型供应商的计算，但迟到结果不会被当作新行程回复。
- `DESKTOP_AGENT_ENABLED` 默认开启，设为 false 可关掉桌面聊天／朗读，原配对、穿门、探索、召回保留。任务工具与多宠仍固定关闭。原历史和用户数据库不用于测试，没有更新部署服务。

原生桌面会在用户发送消息／点击朗读时调用已有供应商；验收使用确定性模型替身及本地 WAV，不消费真实模型额度。自定义外观绑定在标准宠物身份上时沿用该身份的聊天与音色；独立 custom-* 行程尚无人格注册，明确禁用聊天，不回退默认宠物。

## 不可混淆的事实

- 人格、记忆、音色、资产更新可以使旧回复／音频／动画指令失效，但不能删除已创建、已执行任务的事实或幂等记录。
- Task 表示调用结果，Effect 表示效果生命周期，Delivery 表示通知投递情况。玩耍 happy 不表示工具成功，模型文字和动画结束也不能产生任务成功。
- 系统通知调用成功不自动等于用户看见。实施通知适配器时必须定义 delivered 所需的平台证据，用户点击另记回执；没有确认则 unknown。只有确认尚未调用系统通知才可 suppressed。
- unknown 不自动重试；人工重试须提示“可能重复”，保留各次投递尝试。迟到回执不能把实际送达改写成“未发送”。

## 验证与验收边界

第一阶段回归包含：无 request context 的内部聊天、正文伪造身份、不同浏览器 session 下档案 scope、无效账号和宠物、语音 scope/revision、Web/mobile surface 兼容，以及固定截止时间和精确到期拒绝。真实 Chromium＋Electron 流程检查准备、GLB 饰品、出入门、普通／无 code 409 不召回、服务器召回、资源失败和下载中取消。

第二阶段新增：token 与 Cookie 身份冲突、同请求并发、缓存失效和恢复、关闭记忆不落正文、召回／档案变化时丢弃回复与音频、专属音色选择、关闭能力开关；上游契约对照、上下文独立取消、缺失动画回退。真实 Electron 验证聊天发送、朗读和停止、IPC 角色权限、哈希错误拒绝与重新传送。

用户方案的四宠百轮身份测试、50 次虚假成功、四在途调用＋36 活跃效果、竞争条件、四窗口性能和关闭开关后回滚，是后续阶段验收要求，本阶段未完成。36 活跃效果应以提醒为主，不得绕过每账号仅一个专注计时的约束。鸿蒙真机、正式安装包及部署运行数据未在本阶段变更。
