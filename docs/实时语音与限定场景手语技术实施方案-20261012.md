# 宠物聊天系统：实时语音与限定场景手语技术实施方案

> 日期：2026-10-12  
> 项目：`/home/bestfunc/petchat`（WSL Ubuntu-24.04）  
> 交接对象：后续开发 Agent  
> 优先级：P0 实时语音对话；P1 限定场景手语识别

## 0. 执行结论

1. 实时语音直接基于智谱官方 `MetaGLM/glm-realtime-sdk` 协议和浏览器音频模块实现，不采用“整段录音→ASR→HTTP大模型→完整TTS”的高延迟串行方案。
2. 浏览器直连 GLM Realtime；Flask 只签发10分钟短期JWT并返回宠物人设。严禁把长期 `GLM_API_KEY` 放进HTML/JS或接口响应。
3. 首版使用 `server_vad + 16kHz单声道PCM16输入 + PCM流式输出`，保留现有文字聊天和 `/api/tts` 作为降级路径。
4. GitHub没有“国家通用手语+宠物限定场景+浏览器实时+可直接商用”的成品模型。可复用工程骨架，模型必须用自己的中文手语数据训练。
5. 手语首版定义为20个独立意图/短句分类，不是开放词汇连续翻译；识别文字必须经用户确认后发送。
6. 手语评估必须按手语者隔离，禁止随机切分后宣称高准确率。

## 1. 当前代码基线

- Flask应用工厂：`app/__init__.py`
- 路由：`app/routes/chat.py`
- 对话编排：`app/services/chat_service.py`
- 宠物人设：`app/llm/pets.py`
- 配置：`app/config.py`、`.env`

- 3D小窝：`templates/den.html`

- 现有 MediaPipe 已能检测手和人脸，但约10fps、偏交互手势，不能直接作为连续手语模型。

# 第一部分：P0实时语音对话

## 2. 开源方案选择

采用：<https://github.com/MetaGLM/glm-realtime-sdk>

- 智谱官方维护，MIT许可证。
- 与项目已有GLM账号、人设和音色体系一致。
- 包含WebSocket协议、Server/Local VAD、PCM/MP3播放器、实时字幕和打断。
- 官方明确指出移动端优先使用 `server VAD + PCM`。

不要完整搬React Demo；当前项目是Flask+Jinja+原生JS，只抽取或等价实现：

- 麦克风流和AudioWorklet
- 16kHz PCM16编码
- Realtime WebSocket客户端
- PCM连续播放器
- 会话状态机

不采用：浏览器`SpeechRecognition`、整段WAV上传、Flask中转每个音频帧、前端长期API Key。

## 3. 架构

```text
浏览器麦克风
→ AudioWorklet（单声道、重采样16kHz、PCM16）
→ GLM Realtime WebSocket（约100ms/片）
→ Server VAD判定说话起止并托管打断
→ GLM流式生成
→ response.audio.delta
→ PCM播放队列
→ 扬声器

Flask
→ 校验petId/用户
→ 读取宠物人设和白名单音色
→ 用GLM_API_KEY生成10分钟JWT
→ 返回短期会话配置
```

## 4. 后端文件级任务

### 4.1 `app/services/realtime_service.py`（新增）

职责：

- 验证 `GLM_API_KEY` 格式必须为 `{id}.{secret}`。
- JWT Header：`alg=HS256`、`sign_type=SIGN`。
- Payload：`api_key`、`exp`、`timestamp`。
- 用secret做HMAC-SHA256；TTL默认600秒，最大900秒。
- 调用 `pet_registry.build_system_prompt(pet, gender)`，禁止复制另一套宠物人设。
- 服务端按 `PET_TTS_VOICES` 选择voice，忽略客户端任意voice值。

### 4.2 `app/routes/realtime.py`（新增）

接口：

```http
POST /api/realtime/session
Content-Type: application/json

{"petId":1,"petGender":"male"}
```

返回：

```json
{
  "sessionId":"uuid",
  "token":"短期JWT",
  "expiresAt":1791780000,
  "wsBaseUrl":"wss://open.bigmodel.cn/api/paas/v4/realtime",
  "config":{
    "chat_mode":"audio",
    "input_audio_format":"pcm16",
    "output_audio_format":"pcm",
    "turn_detection":{"type":"server_vad"},
    "voice":"服务端白名单音色",
    "instructions":"宠物人设+语音约束"
  }
}
```

约束：

- 响应头 `Cache-Control:no-store`。
- 按session/IP做限流，例如5次/分钟。
- 日志只记sessionId、petId、耗时和状态，严禁记录token/API Key。
- API Key缺失返回503，格式错误返回500并仅写服务端日志。

### 4.3 其他后端修改

- `app/routes/__init__.py`：注册realtime blueprint。
- `requirements.txt`：增加 `PyJWT>=2.8`。
- `app/config.py` 新增：

```text
GLM_REALTIME_URL=wss://open.bigmodel.cn/api/paas/v4/realtime
GLM_REALTIME_TOKEN_TTL=600
GLM_REALTIME_ENABLED=1
GLM_REALTIME_VAD=server_vad
GLM_REALTIME_INPUT_FORMAT=pcm16
GLM_REALTIME_OUTPUT_FORMAT=pcm
```

## 5. 前端文件级任务

新增：

```text
static/js/realtime/audio-capture-worklet.js
static/js/realtime/pcm-player.js
static/js/realtime/realtime-client.js
static/js/realtime/realtime-controller.js
static/js/realtime/realtime-ui.js
```

### 5.1 `audio-capture-worklet.js`

- 使用`AudioWorkletProcessor`，禁止使用已废弃的`ScriptProcessorNode`。
- 浏览器真实输入多为48kHz，不能相信`getUserMedia({sampleRate:16000})`必然生效。
- 在Worklet中重采样至16kHz，单声道Float32转little-endian PCM16。
- 每80～120ms一片，默认100ms。
- 通过transferable `ArrayBuffer`送回主线程，减少复制和GC卡顿。

### 5.2 `pcm-player.js`

- 使用Web Audio API顺序调度chunk，维护`nextPlayTime`。
- 提供`append/reset/pause/destroy`。
- 用户插话时清空未播放队列，避免旧回复继续拖尾。
- 记录buffer underrun次数。

### 5.3 `realtime-client.js`

- 先POST `/api/realtime/session`。
- 浏览器WebSocket不能自定义Header，按官方浏览器SDK方式用短期JWT连接；只允许短期JWT进入URL。
- 收到`session.created`后发送完整`session.update`。
- 处理事件：

```text
session.created
session.updated
input_audio_buffer.speech_started
input_audio_buffer.speech_stopped
input_audio_buffer.committed
conversation.item.input_audio_transcription.completed
response.created
response.audio.delta
response.audio_transcript.delta
response.done
error
```

- 每条客户端事件包含唯一`event_id`和毫秒时间戳。
- 断线重连退避：1、2、4、8秒，最大15秒，加0～300ms抖动。
- 401/过期时重新取JWT。
- 重连后不重放旧音频缓存，避免重复回答。

### 5.4 `realtime-controller.js`

唯一状态机：

```text
IDLE
→ REQUESTING_PERMISSION
→ CONNECTING
→ READY
→ USER_SPEAKING
→ AI_THINKING
→ AI_SPEAKING
→ READY

任意状态 → RECONNECTING / ERROR / STOPPED
```

UI、字幕、按钮和宠物动画只读该状态，禁止各组件自己猜状态。

### 5.5 `realtime-ui.js`和页面

`templates/gpt_me.html`增加：

- “实时语音”入口。
- 权限说明。
- 正在听/思考/说话/重连状态。
- 用户最终字幕和宠物增量字幕。
- 静音、结束按钮。
- 失败后“切换文字聊天”，不无限转圈。

一轮结束后才向历史写一条最终用户消息和一条最终宠物消息；增量字幕不得重复落历史。

第一版只改聊天页。验证稳定后再把同一controller接入`den.html`并用`AI_SPEAKING`驱动宠物口型/头部动作。

## 6. 音频和打断细节

麦克风约束：

```javascript
{
  audio:{
    channelCount:1,
    echoCancellation:true,
    noiseSuppression:true,
    autoGainControl:true
  },
  video:false
}
```

- 一次会话内保持麦克风打开，不要每句重新申请权限。
- `sampleRate`只作为期望值，Worklet必须真实重采样。
- Server VAD负责协议层打断；收到`speech_started`时前端同时停止/清空旧播放队列，保证听感。
- AI播放期间不能直接关闭麦克风，否则无法插话。
- 外放误触发VAD时先调AEC、播放增益和VAD阈值，必须同时测试耳机和扬声器。

## 7. 人设与降级

- Realtime instructions复用`build_system_prompt()`。
- 追加语音约束：口语化、短句、一次2～3句、不读Markdown、允许打断。
- 切换宠物必须销毁旧WebSocket和播放器后再建新会话。
- Realtime失败时保留现有文字请求`/get_gpt_response`和单条`/api/tts`。

## 8. 性能埋点与验收

只记录耗时，不记录原始音频：

```text
t_permission_ms
t_ws_connect_ms
t_session_ready_ms
t_speech_end_to_first_text_ms
t_speech_end_to_first_audio_ms
audio_underrun_count
interrupt_latency_ms
reconnect_count
error_code
```

验收：

- 已授权时点击到READY：P95<1.5秒；首次权限场景P95<2.5秒。
- 停止说话到首段回复音频：P50<1.2秒，P95<2.5秒。
- 开始插话到旧音频停止：P95<300ms。
- 连续20分钟无播放队列越积越长。
- 连续50轮无重复回复、卡死或字幕重复。
- 断网10秒恢复后自动重连，不重放旧音频。
- Realtime不可用时文字和朗读仍可用。

测试：Windows Chrome/Edge、Android Chrome、iOS Safari 17/18；局域网、手机热点、100ms延迟+1%丢包；安静、电视背景声、宠物叫声、外放、耳机、蓝牙切换。

自动化：JWT单测、PCM编码/重采样单测、Mock WebSocket乱序/断线/迟到`response.done`测试、Playwright UI和降级路径；真实麦克风另做人工验收。

# 第二部分：P1限定场景手语识别

## 10. GitHub项目评估

### 10.1 采用浏览器骨架

Google MediaPipe Web Samples：<https://github.com/google-ai-edge/mediapipe-samples-web>

- Apache-2.0。
- 可复用摄像头、Worker及Hand/Pose/Holistic Landmarker模式。
- 它只提取关键点，不提供我们的中文时序模型。

### 10.2 参考训练骨架

`sign-lang-translator-lstm`：<https://github.com/indrajithberlin/sign-lang-translator-lstm>

- MIT；含采集、Holistic关键点、LSTM、平滑和实时推理。
- 只有少量外国手语类别，不能使用其权重和标签。

`Signa`：<https://github.com/V4HD3T/signa>

- 可借鉴50～100独立词、按手语者隔离、Unknown拒识、肩中心归一化、48帧重采样。
- 是土耳其手语，不能使用权重。

### 10.3 暂不接产品

CorrNet：<https://github.com/hulianyuyy/corrnet>

- CVPR 2023连续手语研究代码，支持CSL/CSL-Daily。
- 适合以后开放连续手语研究，但模型重、实时性差、数据许可需确认。
- 公开CSL-Daily checkpoint Test WER约30.1%，不满足限定场景高可靠首版。

最终选择：MediaPipe官方浏览器骨架 + 自采国家通用手语数据 + 自训轻量时序模型 + ONNX浏览器部署。

## 11. 首版词表和交互

由产品、国家通用手语使用者/教师共同冻结20个标准意图。候选：

```text
你好、谢谢、再见、是、不是
开心、难过、生气、害怕、想念
陪陪我、抱抱、摸摸、喂食、喝水
开始游戏、停止、再说一次、我没听清、帮助
```

必须另设`UNKNOWN/非目标动作`。

交互：

1. 点击“开始手语”。
2. 3秒倒计时并提示上半身/双手入镜。
3. 完成一个1～3秒意图。
4. 回到中立姿态自动结束，或点击“完成”。
5. 展示识别文字、置信度和Top-3候选。
6. 用户确认发送或重做。
7. 确认后映射为中文，进入现有文字接口；Realtime开启时可作为`input_text`进入同一会话。

禁止识别后自动发送。

## 13. 特征定义

每帧：

- 左手21点×xyz。
- 右手21点×xyz。
- 上半身8个Pose点（肩、肘、腕等）。
- 左/右手presence mask。
- handedness；不能依赖镜像画面猜左右手。

归一化：双肩中点为原点，肩宽为尺度；缺失手坐标填0且presence=0。训练和前端共享同一预处理版本。第一版不使用全部478个脸部点；若有仅靠表情区分的意图，再加入少量眉眼/嘴角点。

## 14. 数据采集

生产POC：

- 20个意图。
- 至少20名、最好30名手语者。
- 每人每类30次。
- 20×20×30=12,000目标片段。
- 另采3,000～5,000段Unknown：挥手、整理头发、喝水、静止、半截动作、非目标手势。
- 同时保留原视频和关键点，便于复核；默认产品推理不上传视频。

若资源不足，可先做10类×10人×20次=2,000段技术验证，但不得称为生产模型。

覆盖：年龄/体型/手大小/左右利手、衣服颜色、家庭/办公室背景、白天/暖光/弱光、0.8～2米、快中慢速度。

质检：上半身和双手完整入镜；错签、未完成、严重遮挡标`reject`；标签由手语专业人员复核；采集前保存同意记录。

清单：

```csv
clip_id,signer_id,label,path,fps,duration,lighting,background,handedness,reviewer,quality,split
```

## 15. 训练方案

### 15.1 划分

按`signer_id`划分：训练70%、验证15%、测试15%。同一人绝不能跨集合。另保留5名从未参与训练调参的现场验收者。

### 15.2 基线模型

输入`[batch,48,feature_dim]`：

```text
LayerNorm
2层BiLSTM，hidden=128
Dropout=0.30
Attention Pooling
Dense 128 + GELU
Dense 21（20意图+Unknown）
```

- CrossEntropy，label smoothing=0.05。
- AdamW，lr=3e-4，weight_decay=1e-4。
- batch size 64，最多100 epoch。
- 验证Macro-F1连续10 epoch不提升早停。
- 保存数据版本、配置、随机种子、Git commit和最佳checkpoint。

增强：时间伸缩0.8～1.2、裁剪静止帧、轻微关键点噪声、少量手部帧丢失、小范围空间旋转/缩放。左右镜像只能对专家确认不改变语义的类别使用。

若BiLSTM相似类区分不足，再比较轻量TCN/Transformer；基线未稳定前不要上大模型。

### 15.3 拒识初始规则

```text
top1_probability >= 0.85
top1-top2 >= 0.25
连续3个滑窗一致
关键点完整度达标
```

否则返回“没有看清，请重做”。阈值需用验证集做温度缩放和现场校准。

### 15.4 导出

- PyTorch导出ONNX，固定sequence=48，batch可动态。
- 用ONNX Runtime Python对比PyTorch输出，最大绝对误差设门槛。
- 浏览器用ONNX Runtime Web，优先WASM，检测到稳定WebGPU再选WebGPU。
- 模型、标签、预处理meta必须同版本发布，hash写入meta。

## 16. 指标和门槛

输出：Top-1、Macro Precision/Recall/F1、每类Recall、混淆矩阵、Unknown false accept、ECE校准误差、按设备/光线/背景分组结果、浏览器延迟。

POC门槛：未见手语者Macro-F1≥0.85，Unknown误接收≤5%，桌面模型推理<40ms，动作结束后<1秒出结果。

试点门槛：未见手语者Macro-F1≥0.92，关键意图每类Recall≥0.90，Unknown误接收≤2%。任何指标下仍需用户确认，不能宣称零错误。

## 18. 安全与边界

- 麦克风/摄像头必须主动开启并可随时关闭。
- 手语默认本地关键点推理，不上传原视频。
- 加入数据改进计划需单独同意，不得默认勾选。
- UI名称为“限定场景手语辅助识别”，不得写“无差错手语翻译”。
