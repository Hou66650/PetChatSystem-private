# 对话动作与专属陪伴档案

本次在现有 Flask、SQLite、GLM 和 Three.js 上完成第一版。沿用柴犬与哈士奇模型，没有增加模型训练或向量数据库依赖。用户档案影响宠物的称呼、话题与陪伴语气；宠物保留原品种人设，并拥有每位用户独立的昵称和共同回忆。

## 体验入口

- `/den`：打开聊天，试试“走过来，然后坐下”“你安静地趴着陪我”。
- `/companion`：查看、编辑、添加、忘记记忆，暂停记录，清除全部数据。
- `/gpt` 和 `/diary`：读取同一账号的服务器聊天记录。
- 示例：“以后叫我小林，我喜欢画画，平时更喜欢简短安静的陪伴。”刷新后再问宠物如何称呼和陪伴自己。

登录用户以数据库用户 ID 隔离。访客以签名 Cookie 中的随机标识隔离；清理 Cookie 或换浏览器不会继续同一份访客档案。登录后使用账号档案，访客记录不自动合并。旧版缺少身份类型的登录会话，需要重新登录才使用账号档案。之前没有账号归属的浏览器旧记录仍留在原 localStorage 中，不会自动导入或发送给模型。

## 数据与动作流程

`chat_service.handle_chat` 使用服务端历史和档案组织一次结构化模型请求，返回回复、动作计划、记忆候选和忘记目标。历史中的助手动作不会作为未完成任务重复执行。

动作仅允许 come、sit、lie_down、stand、wave、sniff、happy、wander、stop、quiet。每条动作必须引用本轮用户原文，最多三个。模型不能发送 JavaScript、骨骼名称或任意目标坐标。前端负责可达位置、起身过渡、顺序执行、停止和切宠取消；等待 AI 时的人工取消也会使迟到动作失效。

记忆候选仅允许称呼、爱好、不喜欢的事、习惯、计划、陪伴方式、宠物昵称和共同回忆。候选值必须是本轮原文的连续片段，最多80字，每轮最多四条，总量上限80条。临时情绪不作为稳定性格；抽取结果仍可能有误，用户可查看来源、修正或忘记。

用户偏好在同一账号的宠物间共享，宠物昵称与共同回忆按宠物隔离。相同称呼或陪伴偏好更新时替换旧值；相同事项的喜欢与不喜欢互相替换。档案中的个性化陪伴规则直接由明确事实组合，不输出虚构的性格分数。

SQLite 新增 `companion_owners`、`companion_messages`、`companion_memories`，应用启动时幂等建表，不删除原业务表。`app.db.get_db` 改用当前应用配置，测试可使用独立临时库。

## 忘记与暂停的语义

忘记会删除对应记忆，并将旧聊天排除出下一次模型上下文；原聊天仍可单独查看、删除。来源引用只展示在编辑页，不重新送入模型，防止引用中包含已忘记的另一项事实。没有相关事实时模型应明确表示没有记录。

编辑、删除和暂停会推进档案版本，阻止正在生成的旧回复重新写回记忆。全量清除入口会删除该身份下所有宠物的记忆和聊天。跨页面修改会通知同浏览器的实时语音页面结束旧会话；新会话重新读取档案。

暂停期间既不读取长期档案，也不保存新的聊天或记忆；因此该模式不提供跨请求的持久多轮上下文。重新开启后继续使用仍保留的档案。

## 当前边界

- 这是“现有模型 + 用户独立档案”的个性化方案，没有微调出每人一套模型权重，也没有生成新的3D外观。可后续对接 [Mem0](https://github.com/mem0ai/mem0) 等记忆框架，当前规模不需要额外服务。
- 文本回复由现有 GLM 生成，开启 JSON 模式并关闭思考模式。网络和模型延迟仍影响体验；本轮4项语义检查为约2–11秒，不能当作性能承诺。
- 历史持久保存，当前页面取最近60条，模型上下文取最近16条。档案最多80项；大量历史检索和分页属于后续范围。
- 小窝语音输入依赖浏览器 SpeechRecognition，识别后需要点击发送；本轮未用真实麦克风验收。原实时语音页已接入档案与回合存储，但并不驱动另一个页面中的3D场景。一次持续语音会话中的新档案在下次会话加载，原服务自身仍有本轮对话上下文。
- 抽取按原文与类别做约束并过滤部分敏感词，不代表通用的敏感信息识别或完全无误的画像。
- 未进行生产级并发、长期留存、全部浏览器或全部手语能力的测试。猫咪和德牧的后续建模仍暂停。

## v1.4.0：两个界面共用实时语音

小窝操作栏第一个按钮“语音对话”和原聊天页“实时语音”均使用
`RealtimeUI → RealtimeController → RealtimeClient → GLM Realtime`。
麦克风保持打开，服务端 VAD 判定说话结束并自动回复；支持插话、静音、输入设备选择和结束。
小窝原来新增的浏览器 SpeechRecognition 输入流程已移除。

完整语音回合由同一 UI 门面串行提交 `/api/companion/voice-round`，服务端分析用户的最终转写，
记录实际已经说出的回答，不播放第二遍。`surface=den` 可以生成白名单动作；`chat` 始终不执行小窝动作。
后端每轮返回更新后的语音指令，由现有 WebSocket 发送 `session.update`，在分析完成后应用于后续回答。
这一步是异步的，紧接着说的下一句可能早于本轮画像更新。

### 自动画像如何影响陪伴

现有语言模型从明确陈述中提取称呼、兴趣、习惯、计划和陪伴偏好，持久化为有原文依据的记忆。
`behavior_profile()` 再从长期 `style` 偏好生成可解释的保守策略；不需要微调或训练额外模型。
这是“偏好画像”，不会依据兴趣、一次情绪或对话次数推断固定人格。
当前版本支持安静、自然、活泼三种活动节奏，以及简短/自然/展开、温柔/俏皮等说话偏好。
无法明确识别、否定或冲突的表述使用自然默认值。

| 陪伴节奏 | 自主移动速度倍率 | 探索间隔 | 自然回应 |
| --- | --- | --- | --- |
| 安静 | 0.8 | 14–22 秒 | 克制的待机陪伴 |
| 自然 | 1.0 | 4–9 秒 | 保留原本节奏 |
| 活泼 | 1.15 | 2–5 秒 | 开心动作，更常探索 |

移动动画仍按实际速度匹配步频。明确动作请求优先，自由活动开关、手动互动与模型动作能力继续生效。
语音与文字均可建立画像；无需手动填写，档案页用于核对、修改、忘记及暂停。
删除偏好或暂停记忆时，活动策略恢复默认。不会改变模型外观。

### 并发与生命周期

- 回合按 item_id / response_id 配对，等待迟到 ASR 后只归档一次。
- 回合绑定开始时的宠物，按顺序归档；开启麦克风期间点结束也能取消。
- 新语音、切宠、结束、手动互动会使旧动作失效；已结束的完整回合仍可完成归档。
- 语音归档携带会话的 profileScope / profileRevision；换账号、忘记或清除后，旧排队回合不能写回。
- 忘记时重建语音服务会话，避免远端旧上下文继续使用；手动编辑档案通过 BroadcastChannel 结束旧通话。
- 通话期间停止宠物朗读/TTS，防止声音叠加；真实麦克风仍受浏览器权限和系统设备选择影响。

### 验证

在独立临时数据库与浏览器访客中，将合成的中文 PCM 输入真实 GLM Realtime 服务：
“我平时喜欢简短安静温柔的陪伴。现在请你坐下。” → 自动回复、坐下、持久记录安静偏好。
随后在原聊天页语音询问陪伴偏好，能正确回忆，且不执行场景动作。已观察到当前通话的 session.update。
合成音频测试验证协议和应用链路，未替代用户物理麦克风的现场收音测试。
单元测试覆盖账号隔离、暂停/忘记、排队回合、迟到转写、麦克风取消、切宠和动作中断。

语音分析期间面板显示正在整理记忆与动作。超过30秒才返回的动作失效，记忆仍可保存；避免长延迟后突然执行旧指令。
