# 五岛爪印与爪心乐园

## 已实现的首版

按用户提供的爪印布局参考，将四座现有生活岛摆在四个趾垫位置，新建掌垫形的中央公共乐园。保留 `home-islands` 四份现有预览及各自生活场景资源，不重建、不裁切旧岛。乐园入口为 `/park`，首页第五个岛与快捷入口均可进入。

新乐园使用可复现的 `static/js/park-scene.js` 生成场景，首页与乐园共用同一几何来源。包含环形爪印步道、草坪、彩球篮、跳圈、钻筒、平衡板、踏台、树木、长椅、饮水区及入口架。合并静态材质批次后为 8,878 三角面、10 个网格；不包括宠物和首页四岛。当前是首版场景，不是参考照片的写实复刻。

登录用户明确点击“带它入园”后公开一位标准宠物的昵称、外观与位置。公共场地无需好友关系，同场最多 12 位；满员明确提示，不用 NPC 伪造在线人数。列表只显示实际入园且心跳有效的用户。动作包括向伙伴打招呼、玩彩球、嗅闻、休息；可点草坪走动或点伙伴名走近。彩球目前为各宠物的同步展示动作，不是多人争抢同一个物理球。跳圈、钻筒、平衡板和踏台目前是景观道具，尚未完成专属交互。

## 同步与权限

- `/api/park` 返回当前有效在线成员；POST `join/sync/leave` 只从签名登录会话解析身份。
- SQLite 写事务序列化加入与更新，兼容同一个数据库上的多个服务进程。一个账号同时一位入园伙伴；新页面入园使旧访问令牌失效。
- 客户端串行约 2 Hz 同步，画面插值至目标；单次请求超时 4.5 秒。服务端检查坐标、草坪边界、移动距离及更新频率，不能提交别人身份或任意模型 URL。
- 12 秒无心跳即不再显示。主动结束、隐藏页面和离开页面发出退出请求；即使退出请求失败也会到期清理。入园请求晚于退出返回时，撤销迟到的入园结果。
- 私人定制模型暂不公开，不自动替换成通用外观；用户需选择其他标准伙伴。公共返回不含账号、令牌、私人照片或私人模型地址。新成长资源按服务端已有清单选型。
- 不开放自由文字聊天、公开照片上传、陌生人控制宠物或“带走”功能。没有自动社交、好友邀请确认或多人共享物理玩具的实现承诺。
- 这是单服务/共享 SQLite 部署下的公共乐园。跨独立数据库的多服务器、自动分房、数百人并发及公网压力测试尚未实现/验证，不能作为大规模多人架构宣传。

## 验证与复现

```powershell
& .\venv\Scripts\python.exe -X utf8 -m unittest discover -s test -p test_park.py
node test/park_scene.cjs
node test/home_islands.cjs
node test/home_cinematic.cjs
```

浏览器验证需 Node 可加载 Playwright，Chrome 路径可用 `PET_TEST_CHROME` 指定。先在独立终端启动测试服务，再运行脚本：

```powershell
& .\venv\Scripts\python.exe -X utf8 test/park_review_server.py
node test/public_park_render.cjs
```

该服务仅监听 `127.0.0.1:5088`，数据库在临时目录，测试登录入口只在该脚本内注册，不能部署到实际服务。测试生成两个隔离浏览器上下文，验证两账号同时入园、动作同步、移动后仍在线、退出同步、窄屏无横向溢出及首页五岛选择；截图位置打印到终端。测试结束可停止此测试进程。

接口用例覆盖游客、跨站请求、账号作用域、越权令牌、阶段资源解析、非有限坐标、频率限制、满员和过期。四个旧岛原始几何及资源完整性检查保持通过。

## 后续验收与部署边界

本次桌面浏览器验证不能替代鸿蒙真机的 WebView 多宠物性能验收。继续测试同场 4/8/12 位的帧时间、内存、加载失败与网络抖动，再决定人数上限及宠物 LOD。新增乐园本身的低面数不代表多份高精度宠物没有开销。

代码提交不等于已部署：同步运行目录时须先审查其本地改动、数据库与服务版本，不能整体覆盖 `D:\PetChatSystem`，不能执行数据库重置。只有实际服务更新并验证后，才可告知用户正式网页已更新。
