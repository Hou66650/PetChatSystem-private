### B. 猫咪三阶段试点

1. 制作幼年、少年、成年可区分的实际几何；每阶段可编辑源文件、GLB、材质及来源说明齐备。
2. 用固定光照和相机输出正、侧、后、三分之四视角，以及三阶段同画面比较。另做等身高对比，证明差别不是单纯缩放。
3. 尽量保留兼容骨架契约，但根据各阶段比例重新检查关节、权重和动作；复制成年权重不算验收。
4. 静态外形先交审核，技术接入可并行推进，但未通过外形审核不替换默认线上模型。
5. 猫模板至少覆盖 `idle_breathe`、`walk`、`run`、`sit_down`、`stand_up`、`lie_down`、`sleep_loop`、`eat`、`sniff`、`stretch`、`turn_left`、`turn_right`；实际运行还有其他动作映射，必须逐一盘点，不能删掉已有表情或互动能力。

### C. 成长模型接入

- 建立可测试的“宠物种类 + 当前外观 + 成长阶段 → 资源及尺寸参数”解析规则。没有成长资料的现有用户保持原行为；私人定制模型默认保持其身份，不自动换成通用幼宠。
- 新 GLB 的物理体型与旧 growth scale 只能有一个明确的归一化策略，避免重复缩放。模型替换时重算实际变形边界、贴地偏移、碰撞、步幅和相机中心。
- 阶段切换先完成新资源加载并确认有效，再移交可见模型；异步结果带选择/请求标识，切宠后到达的旧结果不得覆盖当前宠物。失败时恢复当前可用外观并提示，不留下空场景。
- Web 和鸿蒙使用同一阶段语义、正确资源身份；测试原生就绪、Web 回退、遮挡合成和透明度，不能只看日志写着 ready。
- 复用现有动态本地缓存。当前 Web 公共 GLB 缓存会去掉 `v` 查询参数并使用 ETag/Last-Modified 重新校验，不能假定改 `?v=` 就产生独立缓存。阶段及不兼容资产采用明确独立路径，并核对原生缓存键、更新/损坏处理。
- 只加载当前需要的资源，不在首页下载四种宠物的所有阶段。切换释放旧 GPU 资源和无用下载，防止缓存越多内存越高。
- 不强行引入 Draco、KTX2、morph 等依赖；只有两端实际解码/渲染验证后才使用。先用双方可读取的自包含 GLB。

猫咪流程成立后完成柴犬、哈士奇、德牧三阶段，逐种验证，不把猫骨架套到所有狗上。保留原来的动作/表情及毛色选择语义。若某外观变体暂不支持成长模型，明确显示/记录回退，不伪装成已支持。

后续每批回报：完成的具体资产/代码、对比截图或录屏路径、测试命令与结果、实际性能数据、未完成项、提交 SHA/tag、是否推送、是否部署。不能把构建成功写成真机可用，不能把静态截图写成动作验收。

全任务完成需同时满足：四种宠物三阶段真实造型交付、Web/鸿蒙一致选型、缓存与回退可用、现有行为无回归、性能有可复查数据、美术及真机验收完成。若当前只能完成部分，明确标记阶段，不把整个任务宣布完成。
