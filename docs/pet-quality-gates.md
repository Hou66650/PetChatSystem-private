# 私人宠物模型质量关卡

生成成功只代表取得草稿。新模型、旧的 reviewed 模型都必须有与当前素材匹配的制作端质量记录，才能确认外貌、绑定、完成动作验收或进入小岛/传送门。没有记录、记录过期和 unknown 均不放行。普通网页没有写入质量结论的接口。

## 当前已实现的范围

1. inputs：云端计费提交前核对同一动物、照片姿态/尾巴一致性。现阶段由制作人员审核；没有可靠的自动姿态一致性识别器。已有云端任务继续查询，不重复收费。
2. geometry：原始网格必须经过身体结构审核。生成后处理输出三处后部截面的显著分支数量作为诊断；这依赖 -Y 朝向，不能当作通用解剖识别。模板适配在三个截面中至少两处多分支时拒绝蒙皮，不自动切除网格。不能定位尾巴也会拒绝。
3. rig：自动检查实际脚掌权重覆盖（每只脚至少 10 个权重 ≥0.25 的顶点、加权组的几何中心与脚骨距离不超过最大体长 25%）。这是粗筛，不能证明语义正确，仍需审核关节位置、腋下/腹部/尾根及每条肢体的权重归属。Blender 热权重失败不再静默忽略。
4. motion：对 12 个动作各采样 5 帧的实际变形网格，检查有限坐标、边拉伸及行走/跑步是否真正驱动网格。边长超过静止长度 8 倍且增加超过最大体长 5% 才作为严重拉伸失败，避免极短接缝误报。脚掌滑动、穿地、自相交与身份外貌仍须播放动作审核。

机器检查不会自动把上述阶段标记为 pass，也不承诺任意猫狗通用自动绑骨。现有站立猫模板仍是草稿；坐卧、卷尾、肢体粘连和其他物种需在 Blender 中修正/重新定位关节或采用对应物种骨架。当前版本没有实施通用语义分割、自动删尾、自动重拓扑或关节预测。这些需要有标注的验证集，不能用简单空间阈值替代。

## 制作端审核操作

先部署新代码并正常启动服务，创建 `pet_studio_quality` 表。使用服务所用的 Python 环境；Windows 建议 `python -X utf8`。CLI 直接使用 SQLite，不启动 Flask、不重置运行中的任务。备份按部署流程执行；不要将数据库、审核包或用户照片加入 Git。

从私人工作室 API/数据库取得待审核 task ID。只读导出到新的私有目录：

```powershell
python -X utf8 scripts/pet_quality_review.py --database D:\PetChatSystem\book.db export --task TASK_ID --output D:\pet-review\case-input
```

检查照片：同一动物、方向标签正确、站立主参考、姿态及尾巴位置一致。若仅有旧照片/遮挡图，记录无法确定的部位，不把猜测记为通过。上传模型没有照片时，可记录“直接导入，无参考照片”；geometry 审核仍必须完成。

制作人员逐阶段记录结论（pass/fail/unknown），必须提供说明与实际截图/录像等证据文件：

```powershell
python -X utf8 scripts/pet_quality_review.py --database D:\PetChatSystem\book.db review --manifest D:\pet-review\case-input\manifest.json --stage inputs --result pass --notes "已核对同一动物与站立姿态，尾部方向一致" --evidence D:\pet-review\photos-contact-sheet.png
```

此后用户可发起原有的显式计费生成。模型生成后重新导出到另一个新目录。可生成八视角素模证据（不修改源 GLB）：

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --disable-autoexec --python scripts/blender/inspect_pet.py -- D:\pet-review\case-model\model.glb D:\pet-review\case-model-views
```

核对头、躯干、四肢、尾巴和配饰，特别检查尾根/腹部/腋下。对本次双尾案例，geometry 应记 fail，说明“原始网格双尾”，附后视/俯视证据；保留私人草稿用于修复。不要为了继续流程强行记 pass。

geometry 通过后用户可确认外貌并运行绑定。绑定完成后重新导出；在 Blender 检查关节与权重，播放完整动作和转头测试，分别记录 rig、motion。两阶段通过后网页才能记录用户动作验收、装备。CLI 不会装备、调用云端或创建付费任务。

证据文件保留在受控审核目录，数据库保存说明和文件哈希，不保存本机路径。CLI 验证审核包文件哈希，并在写事务中重新检查当前素材；审核期间文件/骨架改变则拒绝写入。重新审核上游阶段会清除下游结论及装备指针，需要重新审核并由用户再次装备。应按阶段顺序操作。

## 指纹和回退

- inputs 绑定所有参考照片（包括 detail）。geometry 同时绑定照片和原始模型；rig/motion 进一步绑定 adapted 文件、绑定任务 ID、source_hash、完整绑定报告。
- 重新上传、重新绑定或更换报告后，旧结论不能继续使用。旧版没有质量记录的已装备模型，在新请求中回退到标准外观；已经打开的页面需刷新。私人草稿和照片不删除。
- 质量未通过时允许所有者下载私人草稿修复；不通过小岛/有效行程的模型接口交付。已打开页面中的模型无法远程从内存中收回。
- 审核身份是有数据库访问权限的本地制作人员；本工具不是多人角色权限系统。不能开放为普通用户可调用的 HTTP 接口。

## 后续自动化验收标准

替代人工关卡前，需要猫/狗、长毛、卷尾、坐卧、多余肢体等有标注的正反样本。部位分割与关节拟合必须输出置信度，低置信度进入 unknown。异常分支仅在部位归属和连接关系明确、切除后补面/UV/贴图与动作复验均通过时才允许生成修复候选。重生成仍需原有计费确认，不能自动重试收费。

## 本次验证

- 本机最新用户原始 GLB：三个后部截面均为两个显著分支，在蒙皮前被拦截。
- 标准 cat-v3 GLB：脚掌覆盖和 12 个动作实际网格采样通过，仍保持待人工质量审核。
- API 回归覆盖缺失/旧版审核、全勾选绕过、素材与任务变化、撤销、逐阶段通过，以及私人小岛和传送门读取。
