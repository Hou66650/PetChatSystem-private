# 爪心乐园迁移

源代码以 `origin/codex/v1.4.0@c077b62` 为准。Web 与 Harmony/ArkWeb 使用同一个 `/park`、`public-park.js`、`park-scene.js` 和 `navigation.json`；Harmony 只另做触控布局、像素预算与云层降级，不存在另一份中心岛几何。

实际运行的 `play.glb` SHA256 为 `65a86bf8c4d2d4f8324659f2dadd3dc54bcf25fb9513a072a68131f36efa6d0f`。D 盘运行目录、Web 工作区与远端一致。UE 直接导入这份既有 Blender 模型，首页使用其 `preview.glb`，没有重新设计中心岛。已暂存的 `entrance-crafted.glb` 尚未替换 Web 运行版本，本次也不叠加重复门楼。

## 实现

- 原生首页调整为四趾岛与中心掌垫岛，选择第五项「爪心乐园」、镜头过渡、独立精细场景与返回群岛。
- 原生 Slate 乐园面板：选择四种标准伙伴、明确入园、结束游玩、手动走动、招呼、休息、自主游玩、低桥和猫耳隧道、界面显隐。
- `/api/native/v1/park` 使用已有 bearer 账号；与 Web 相同的 `park_presence`、12 人容量、12 秒超时、令牌撤销及服务端障碍/设施校验。共用数据库时不是独立假房间。进入场景本身不会公开宠物。
- 复用 Web 的成长档案和公共外观元数据解析服务，不改变原有经济、私模或传送记录；客户端渲染当前使用已 Cook 的四宠标准骨骼资产，成长阶段模型、购买毛色和配饰尚未完成原生显示适配。不得把默认模型当成这些外观已迁移。
- 原生轻量自主决策不调用大模型；草坪 A* 按共享障碍配置执行，设施通过服务器确认后沿相同三维路线前进，桥尽头折返，隧道按体型限高。

## 尚未对齐

Web 的完整效用评分、分阶段社交/玩球计划、过渡动画和成长外观/配饰仍需进一步适配；原生版当前具有探索、招呼、休息和设施选择，不能称为完整行为等价。多人远程实体使用插值和软避让，不是多人刚体物理。

编译、Cook、实机截图和隔离联调结果写入 `Qualification/public-park-evidence.json`。原生自动回归与实际手工鼠标验收分开记录；不以启动或导入成功代替画质、所有动作或帧率达标。

## 复现

1. 从固定源提交取得 `static/models/paw-commons-v2/{play,preview}.glb` 到 `Saved/Art/PawCommons`。
2. UE `-ExecutePythonScript=Scripts/import_public_park.py`，基于已存在的四岛首页导入；仅修改原生中心岛和首页布局。
3. BuildCookRun Shipping；`Start-NativeService.ps1 -Port 5013 -Fixture` 启动隔离账号库，运行 `Test-PublicPark.ps1 -ThroughHome`（不传此开关则直接加载中心岛）。测试最多等待 320 秒，正常游玩不受测试时限影响。
4. `python -m unittest discover -s test -p test_native_park.py` 检查鉴权、共享房间、绕障碍和设施进度。
